# Подключение Postgres

У Codex нет своего окна «введите строку подключения» для плагинов, поэтому её
задаёт агент — то есть вы, по этой инструкции. Спросите у пользователя адрес
базы, если он его ещё не назвал.

## 1. Проверьте, что есть `uv`

Сервер запускается через `uvx`:

```sh
command -v uvx
```

Нет — поставьте и скажите пользователю перезапустить Codex, чтобы новый PATH
подхватился:

```sh
curl -LsSf https://astral.sh/uv/install.sh | sh
```

## 2. Запишите строку подключения

Файл `~/.codex/.env` — Codex читает его при старте, и переменные оттуда
достаются MCP-серверам. Добавьте туда строку, **не трогая остальные**:

```
DATABASE_URI=postgresql://user:password@host:5432/dbname
```

Правила:

- один параметр — одна строка, кавычки не нужны;
- если пароль содержит `@`, `/`, `:` или `#`, закодируйте его процентами
  (`p@ss` → `p%40ss`);
- база в докере на этой же машине — обычно `localhost`, а не имя сервиса;
- managed-база (RDS, Supabase, Neon) почти всегда требует TLS: добавьте
  `?sslmode=require` в конец.

Никогда не кладите строку подключения в `config.toml`, в репозиторий проекта и
в переписку — только в `~/.codex/.env`.

## 3. Перезапустите сессию

MCP-серверы поднимаются один раз при старте сессии. Пока пользователь не
перезапустит Codex, инструменты будут падать со старой ошибкой — скажите об
этом прямо.

## 4. Проверьте

Позовите `list_schemas`. Пусто или ошибка — разбирайте по тексту:

| Симптом | Причина |
|---|---|
| `env var DATABASE_URI is not set` | строка не попала в `~/.codex/.env` либо сессию не перезапустили |
| `password authentication failed` | логин или пароль; проверьте процентное кодирование |
| `could not translate host name` | хост недоступен с машины пользователя (VPN, докер-сеть) |
| `no pg_hba.conf entry` | база требует TLS — добавьте `?sslmode=require` |
| `command not found: uvx` | шаг 1, и Codex после установки надо перезапустить |

## Что плагин умеет и чего не умеет

Сервер запущен в режиме `restricted`: только чтение и безопасные запросы —
схема, `EXPLAIN`, здоровье базы, подсказки по индексам, `SELECT`. Записи,
`DDL` и длинные блокирующие запросы он отклонит сам.

Пользователю нужна запись — это осознанное решение, и делается оно отдельным
сервером в его собственном `~/.codex/config.toml`, а не правкой плагина
(правки внутри плагина затрёт следующее обновление маркетплейса):

```toml
[mcp_servers.postgres-rw]
command = "uvx"
args = ["--with", "mcp[cli]<2", "postgres-mcp", "--access-mode=unrestricted"]
env_vars = ["DATABASE_URI"]
```

Предупредите, что в этом режиме агент может изменить и удалить данные.
